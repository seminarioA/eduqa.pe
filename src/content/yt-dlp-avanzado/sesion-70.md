# Abrir un issue antes de implementar

Antes de escribir una feature nueva, la guía pide abrir un issue que explique la propuesta y al menos un caso de uso.

> Doc: [Adding new feature or making overarching changes](https://github.com/yt-dlp/yt-dlp/blob/master/CONTRIBUTING.md#adding-new-feature-or-making-overarching-changes)

# Razón

La discusión previa permite decidir si la feature es deseada y acordar detalles de implementación.

# Pull request sin discusión

La guía advierte que un PR de feature no discutido puede requerir cambios grandes o ser rechazado.

# Documentación y estilo

La misma regla aplica a cambios de documentación, estilo de código y modificaciones transversales de arquitectura.

```opcion-multiple
# Enunciado
¿Qué debe hacerse antes de implementar una feature nueva?

# Opciones
- Abrir un issue con la propuesta y un caso de uso
- Escribir directamente el PR completo
- Cambiar primero el formatter
- Crear un release

# Correcta
1

# Explicación
La discusión previa valida alcance y dirección antes de invertir en implementación.

# Pista
La guía pide acordar la feature primero.
```
